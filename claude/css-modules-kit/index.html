B. Downstream-embedder cases

  • B1. Embedder coupling to the findBand class no downstream change needed

    A downstream embedder's stylesheet excludes the find band by its literal global class (div:not(.findBand) in a height rule). Hashing findBand would break that exclusion. Rather than change the embedder (an earlier draft keyed hawk off data-unsearchable, but that overloads a search-semantics attribute and couples by accident), the viewer keeps findBand as a deliberate public class: the band renders clsx(styles.findBand, "findBand") — hashed class for the viewer's own styling, unhashed findBand as a documented, rule-less hook for embedders. So the embedder's existing selector keeps matching with no downstream change. A sweep of every class this branch converts found no other literal coupling in the embedder; its remaining global couplings (header-nav, tab-content, markdown-content) are unaffected (this branch doesn't touch them).

    Embedder before/after checklist (everything else is covered by this report): 1) Ctrl+F on an embedded sample detail — find band stays a compact top-right overlay, content behind keeps full height; 2) the embedder's own chrome around the viewer loads without "No QueryClient set" / "App config not loaded" (it consumes the react-query embedder exports, merged upstream in ts-mono main #473); 3) one glance over an embedded log list, sample detail, and transcript for style bleed — no specific risk known. Items 2–3 and the earlier data-unsearchable approach were verified 08-20 against real embedder data; item 1 re-verifies against the preserved global findBand class in the smoke test.
